# SAT-модуль — план по этапам

Источник: ТЗ «Курсы SAT» (ноябрь 2026) и разбор: https://claude.ai/artifact/V7NU6sLCcaYvHGWdZ2QsU7
Решения: один сайт, курсы — вкладки в кабинете ученика. Менторские таблицы не трогаем, SAT — новые таблицы.
Роли: руководитель (всё), ментор, куратор SAT, учитель SAT (видит всех SAT-учеников, правит свои группы и замены),
старший учитель SAT (правит все SAT-группы), ученик, родитель (ссылка). Одна персона — несколько ролей.
Группа ↔ учитель/куратор с датами; замена на уровне занятия; перевод ученика = новое зачисление с датой.
Рейтингов в SAT нет. Каждый этап: миграция + файл отката, тесты прав в локальном Postgres, сборка, e2e.

## Этап 1 — Фундамент: роли, права, группы ✅ сделано (10 ноября 2026)
Код: migration-sat-1.sql (+ rollback-sat-1.sql), /admin/team, /admin/groups, вкладки курсов в /dashboard,
.github/workflows/db-backup.yml (docs/BACKUP.md). Проверки: supabase/tests/run.sh (права в Postgres),
tests/e2e (35 сценариев в браузере на локальном стеке GoTrue + PostgREST).
Включить: 1) Supabase → SQL Editor → supabase/setup-all.sql → Run; 2) влить ветку; 3) секреты для копий (docs/BACKUP.md).
Решения по ходу:
- Руководитель/ментор = profiles.role 'admin' (вся менторская часть как раньше); только SAT = 'staff'.
  Роль в profiles выставляется сама по ролям сотрудника (триггер); менять её может только руководитель.
- Все ученики на момент миграции зачислены на «Менторство». Новый ученик в «Аккаунтах»: курс «Менторство» или «Только SAT»;
  ученики только SAT скрыты из менторского реестра и видят в кабинете только вкладку SAT.
- Учителя SAT не видят таблицу students (менторские данные) — только имя/класс/школу через функции sat_roster и поиск.
- Supabase создаёт пользователя в два шага (app_metadata пишется после вставки), поэтому пустую карточку ученика
  у нового сотрудника убирает сервер в /api/admin/team.
- Отключённый сотрудник: вход заблокирован (ban), права в базе пропадают сразу, история остаётся.

- ПЕРВЫМ ДЕЛОМ: ежедневная резервная копия базы через GitHub Actions (pg_dump ночью, хранение 90 дней,
  зашифрованный артефакт). Алибек один раз кладёт строку подключения к базе в GitHub → Settings → Secrets.
  Заодно будит бесплатную базу каждую ночь (не уснёт на каникулах).
- staff_roles, функции прав (can_view_student, can_edit_group) вместо is_admin(); текущий admin = руководитель
- courses, streams, groups, group_staff, enrollments (цель, дата SAT)
- Вкладки курсов в кабинете ученика
- «Команда» (/admin/team) — только руководитель. Расширить существующую /admin/accounts (сейчас только ученики):
  * «+ Сотрудник»: ФИО, логин, роли галочками (руководитель / ментор / куратор SAT / учитель SAT / старший учитель),
    город, группы сразу при создании → временный пароль показывается один раз + кнопка «Скопировать для WhatsApp»
  * список сотрудников: роли чипами, группы, последний вход; изменить роли, сбросить пароль, отключить (не удалять — история в журнале)
  * массовое создание: вставить список строк «ФИО; роль; группа» → предпросмотр → создать всех, пароли одной таблицей
  * защита: нельзя снять роль руководителя с последнего руководителя; все изменения ролей — в журнал
  * создание через серверный маршрут с service role (как сейчас для учеников), права проверяются на сервере
- «Группы» (/admin/groups): создать поток и группу, назначить учителя и куратора из списка, добавить учеников поиском,
  перевод ученика в другую группу с датой, замена учителя с даты
- Нужно от Алибека: список сотрудников и ролей; кто старший учитель; группы потока 3 (не блокирует — можно заполнить позже)

## Этап 2 — Занятия ✅ сделано (10 ноября 2026)

Решения по ходу:
- Расписание по примеру (Вт Math 17:00, Чт Verbal 18:30, Пт Практис 17:00, по 90 мин) — кнопка в группе, правится на сайте.
- Занятия создаются из расписания сами (до 4 недель вперёд); изменение расписания пересоздаёт будущие неотмеченные.
- Отмечают учитель и куратор группы на дату занятия, учитель на замене, старший учитель и руководитель. Будущие занятия не отмечаются.
  Окно правки 3 дня (руководитель и старший учитель — без ограничения). Отдельной настройки «кто отмечает» пока нет — оба могут.
- Посещаемость: «опоздал» = был. ДЗ: «частично» = половина. Отменённые занятия не считаются.
- «Не отмечено» у учителя — только занятия, которые он вёл (в группе на дату или на замене), за последние 3 дня.
- schedule_slots, lessons, lesson_marks; «Моё расписание · неделя», «Занятие сегодня», «Не отмечено»
- перенос/замена занятия; окно правки 3 дня; кто отмечает присутствие (настройка, по умолчанию куратор)
- Нужно: расписание групп (дни, время, длительность)

## Этап 3 — Результаты и кабинет ученика ✅ сделано (10 ноября 2026, на примерных данных)
Код: migration-sat-3.sql (+ rollback-sat-3.sql), /admin/results «Результаты» (таблица группы, пробные экзамены, практисы),
кабинет ученика SAT по макету. Проверки: supabase/tests/sat-3-rights.sql, tests/e2e/e2e_sat3.py.
Решения по ходу:
- Темы — стандартный список Digital SAT (30 тем, Math/Verbal), правятся в таблице sat_topics; заменить на свои, когда пришлют.
- Мок общий для потока (создаёт руководитель/старший учитель), баллы Verbal и Math 200–800, итог считается сам; вносят учителя групп.
- Практис — у группы, тема + число задач; до 3 попыток, засчитывается лучшая. Цвета: <50% красный, 50–79 жёлтый, 80+ зелёный.
- «Путь к цели» = (последний мок − первый) / (цель − первый). Статус: риск — посещаемость < 75%, ДЗ < 60% или падение между моками;
  растёт — +30 и больше; иначе «стоит на месте».
- Комментарий: «только команда» или «увидят ученик и родитель»; ученик видит только второй тип.
- Ввод: вручную или «Вставить из таблицы» (ФИО; Verbal; Math — прямо из Google Таблиц). Полный импорт CSV — этап 4.
- sat_topics, practices/practice_results, mocks/mock_results; ручной ввод и CSV
- Кабинет ученика: цель и путь к ней, моки, история практисов (цвета 50/80%), «что перерешать» (2–3 попытки), дни до SAT
- Таблица группы для учителя
- Нужно: список тем SAT, формат моков, цели учеников

## Менторство: отчёты родителям (ноябрь 2026) — сделано

1. После индивидуальной встречи ментор заполняет в журнале блок «Отчёт о встрече для родителей» (что получилось / над чем работаем / чем помочь дома). Видит только ментор.
2. Раз в месяц на странице Менторство → «Родителям» отчёт собирается списком из этих блоков и цифр месяца (без ИИ). Ментор дописывает общее впечатление и про групповые встречи (общий текст можно вставить всем).
3. У каждого ученика своя Telegram-группа (ученик, родители, ментор). Бот добавляется в группу, привязка — `/connect КОД` (код на странице). Отчёт уходит ботом, кнопки «Прочитали» / «Есть вопрос» видны ментору.
4. Бот принадлежит компании: создаётся в @BotFather, токен — `TELEGRAM_BOT_TOKEN` в Vercel. Секрет вебхука выводится из токена.
5. Миграция `migration-parent-reports.sql` (откат `rollback-parent-reports.sql`), тест `tests/e2e/e2e_reports.py`.

## Менторство: план года для родителей (ноябрь 2026) — сделано
1. Фокусы месяцев хранятся на сайте (таблица program_plan), первый раз заполнены из плана «Менторская работа до мая». Ментор правит на странице Менторство → Ещё → «План года».
2. Родители видят «План года» в своём кабинете: пройденные месяцы бледные, текущий и следующий раскрыты. Вариант для 10 класса — только десятиклассникам.
3. Месячный отчёт сам добавляет блок «Что дальше»: тема следующего месяца, результат (или вариант для 10 класса) и «Как помочь дома».
4. Миграция `migration-program-plan.sql` (откат `rollback-program-plan.sql`), тест `tests/e2e/e2e_plan.py`.

## Менторство: чеклист и напоминания об отчётах родителям (ноябрь 2026) — сделано
1. На странице «Родителям» сверху чеклист месяца: кому отчёт ушёл, кому нет; клик по имени открывает карточку.
2. На главной (реестр) в последние 3 дня месяца и 1–5 числа плашка «Отчёты родителям за … : отправлено X из Y», пока не всё отправлено.
3. Личные напоминания в Telegram: «Родителям» → «Напоминания в Telegram» → «Подключить» (ссылка на бота). Vercel Cron каждый день в 09:00 по Алматы (`/api/cron/report-reminders`, `CRON_SECRET`), пишет только в окно конца месяца и если не всё отправлено, не чаще раза в день.
4. Миграция `migration-mentor-reminders.sql`, тест `tests/e2e/e2e_reminders.py`.

## Этап 4А — кабинет SAT ученика (ноябрь 2026) — сделано
1. SAT целиком в светлой теме (страницы сотрудников SAT и вкладка SAT ученика), менторство тёмное. `<html data-theme="sat">`, переменные и переопределения в globals.css.
2. Моки: Verbal и Math разными цветами; официальный SAT в той же динамике (вносит ученик или сотрудник, `sat_official_results`); место в группе по последнему моку «5 из 15» — только своё (`my_mock_rank`).
3. «Расписание» на 2 недели: занятия с временем и длительностью, office hours фиолетовым (`schedule_slots.kind`, `lessons.kind`; не отмечаются и не идут в посещаемость).
4. Домашка: учитель пишет при отметке занятия (`lessons.homework`), ученик видит «К следующему занятию» и статус прошлых.
5. «Что перерешать»: все темы, раскрываются с историей; кнопка «Практис по теме» — ссылка из `sat_topics.practice_url` (Результаты → Практисы → «Ссылки»).
6. Название группы крупно; ачивки: серии, моки, практисы, месяц.
Миграция `migration-sat-4.sql` (откат `rollback-sat-4.sql`), тест `e2e_sat4.py`.
