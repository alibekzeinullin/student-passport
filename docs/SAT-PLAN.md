# SAT-модуль — план по этапам

Источник: ТЗ «Курсы SAT» (ноябрь 2026) и разбор: https://claude.ai/artifact/V7NU6sLCcaYvHGWdZ2QsU7
Решения: один сайт, курсы — вкладки в кабинете ученика. Менторские таблицы не трогаем, SAT — новые таблицы.
Роли: руководитель (всё), ментор, куратор SAT, учитель SAT (видит всех SAT-учеников, правит свои группы и замены),
старший учитель SAT (правит все SAT-группы), ученик, родитель (ссылка). Одна персона — несколько ролей.
Группа ↔ учитель/куратор с датами; замена на уровне занятия; перевод ученика = новое зачисление с датой.
Рейтингов в SAT нет. Каждый этап: миграция + файл отката, тесты прав в локальном Postgres, сборка, e2e.

## Этап 1 — Фундамент: роли, права, группы ✅ сделано (10 ноября 2026)
Код: migration-sat-1.sql (+ rollback-sat-1.sql), /admin/team, /admin/groups, вкладки курсов в /dashboard,
.github/workflows/db-backup.yml (docs/BACKUP.md). Проверки: supabase/tests/run.sh (права в Postgres),
tests/e2e (35 сценариев в браузере на локальном стеке GoTrue + PostgREST).
Включить: 1) Supabase → SQL Editor → supabase/setup-all.sql → Run; 2) влить ветку; 3) секреты для копий (docs/BACKUP.md).
Решения по ходу:
- Руководитель/ментор = profiles.role 'admin' (вся менторская часть как раньше); только SAT = 'staff'.
  Роль в profiles выставляется сама по ролям сотрудника (триггер); менять её может только руководитель.
- Все ученики на момент миграции зачислены на «Менторство». Новый ученик в «Аккаунтах»: курс «Менторство» или «Только SAT»;
  ученики только SAT скрыты из менторского реестра и видят в кабинете только вкладку SAT.
- Учителя SAT не видят таблицу students (менторские данные) — только имя/класс/школу через функции sat_roster и поиск.
- Supabase создаёт пользователя в два шага (app_metadata пишется после вставки), поэтому пустую карточку ученика
  у нового сотрудника убирает сервер в /api/admin/team.
- Отключённый сотрудник: вход заблокирован (ban), права в базе пропадают сразу, история остаётся.

- ПЕРВЫМ ДЕЛОМ: ежедневная резервная копия базы через GitHub Actions (pg_dump ночью, хранение 90 дней,
  зашифрованный артефакт). Алибек один раз кладёт строку подключения к базе в GitHub → Settings → Secrets.
  Заодно будит бесплатную базу каждую ночь (не уснёт на каникулах).
- staff_roles, функции прав (can_view_student, can_edit_group) вместо is_admin(); текущий admin = руководитель
- courses, streams, groups, group_staff, enrollments (цель, дата SAT)
- Вкладки курсов в кабинете ученика
- «Команда» (/admin/team) — только руководитель. Расширить существующую /admin/accounts (сейчас только ученики):
  * «+ Сотрудник»: ФИО, логин, роли галочками (руководитель / ментор / куратор SAT / учитель SAT / старший учитель),
    город, группы сразу при создании → временный пароль показывается один раз + кнопка «Скопировать для WhatsApp»
  * список сотрудников: роли чипами, группы, последний вход; изменить роли, сбросить пароль, отключить (не удалять — история в журнале)
  * массовое создание: вставить список строк «ФИО; роль; группа» → предпросмотр → создать всех, пароли одной таблицей
  * защита: нельзя снять роль руководителя с последнего руководителя; все изменения ролей — в журнал
  * создание через серверный маршрут с service role (как сейчас для учеников), права проверяются на сервере
- «Группы» (/admin/groups): создать поток и группу, назначить учителя и куратора из списка, добавить учеников поиском,
  перевод ученика в другую группу с датой, замена учителя с даты
- Нужно от Алибека: список сотрудников и ролей; кто старший учитель; группы потока 3 (не блокирует — можно заполнить позже)

## Этап 2 — Занятия ✅ сделано (10 ноября 2026)
Код: migration-sat-2.sql (+ rollback-sat-2.sql), /admin/lessons «Занятия», расписание и недели потока на /admin/groups,
посещаемость/ДЗ/ближайшие занятия во вкладке SAT. Проверки: supabase/tests/sat-2-rights.sql, tests/e2e/e2e_sat2.py.
Решения по ходу:
- Расписание по примеру (Вт Math 17:00, Чт Verbal 18:30, Пт Практис 17:00, по 90 мин) — кнопка в группе, правится на сайте.
- Занятия создаются из расписания сами (до 4 недель вперёд); изменение расписания пересоздаёт будущие неотмеченные.
- Отмечают учитель и куратор группы на дату занятия, учитель на замене, старший учитель и руководитель. Будущие занятия не отмечаются.
  Окно правки 3 дня (руководитель и старший учитель — без ограничения). Отдельной настройки «кто отмечает» пока нет — оба могут.
- Посещаемость: «опоздал» = был. ДЗ: «частично» = половина. Отменённые занятия не считаются.
- «Не отмечено» у учителя — только занятия, которые он вёл (в группе на дату или на замене), за последние 3 дня.
- schedule_slots, lessons, lesson_marks; «Моё расписание · неделя», «Занятие сегодня», «Не отмечено»
- перенос/замена занятия; окно правки 3 дня; кто отмечает присутствие (настройка, по умолчанию куратор)
- Нужно: расписание групп (дни, время, длительность)

## Тарифы
Пока всё бесплатно (Supabase Free + Vercel Hobby). Напоминания — через pg_cron в базе, не через Vercel cron.
Файлы — ссылками на Google Drive, не загрузкой. Переход на Supabase Pro ($25/мес): база > ~300 МБ,
нужна загрузка файлов, или пришло предупреждение от Vercel/Supabase.
